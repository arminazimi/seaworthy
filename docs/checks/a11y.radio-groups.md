# a11y.radio-groups

Radio buttons or checkboxes that share a `name` are not inside a labelled group.

## Why it matters

A set of radio buttons answers one question: "Size: small, medium, large". Each button has its own label ("Medium"), but without a group label a screen reader user hears only "Medium, radio button, 2 of 3" and not what is being chosen. The `<fieldset>` and `<legend>` pair, or an ARIA group with a name, gives the question. The same holds for a set of checkboxes that belong together.

## What it checks

Radio buttons (or checkboxes) with the same non-empty `name` inside the same `<form>`, or on the same page when there is none, in groups of two or more. Each group is accepted when the controls are inside:

- a `<fieldset>` whose first `<legend>` child has text (or that has `aria-label` or `aria-labelledby`), or
- an element with `role="radiogroup"` or `role="group"` and a non-empty `aria-label` or `aria-labelledby`.

One report is made per group, at the first control that has no label. A single radio button, controls with different names, `type="hidden"` inputs, and hidden controls are not grouped.

## How to fix

```html
<!-- before -->
<label><input type="radio" name="size" value="s"> Small</label>
<label><input type="radio" name="size" value="m"> Medium</label>

<!-- after -->
<fieldset>
  <legend>Size</legend>
  <label><input type="radio" name="size" value="s"> Small</label>
  <label><input type="radio" name="size" value="m"> Medium</label>
</fieldset>
```

Use `<fieldset>` and `<legend>` first; they need no ARIA. If the layout cannot use a fieldset, use `role="radiogroup"` (or `role="group"` for checkboxes) with `aria-labelledby` pointing at the question. There is no automatic edit, because the report cannot know the question.

## Options

None.
