# i18n.switcher

A visible link that carries an `hreflang` attribute — the standard language-switcher markup — lands on a page other than the one the same page declares as its alternate for that language.

## Why it matters

The language switcher is how a person, and any agent reading the page's links, moves between translations of the content they are looking at. When the "Deutsch" link on the English article opens the German home page — or the current page itself, or a page the build never served — the page breaks the promise its own `hreflang` set makes: visitors lose their place, and the machine that follows links to find the German copy of this exact article lands on the wrong language's wrong page.

## What it checks

A link is a switcher when, and only when, it is a **visible `<a>` element that carries a non-empty `hreflang` attribute and an `href`**. Visible means neither the link nor any ancestor has `hidden` or `aria-hidden="true"`, and the link is not inside `script`, `style`, `template`, `noscript`, `svg`, or `math` markup. Nothing is guessed from link text ("English", "EN", "Deutsch") or from nav class names: a false accusation costs more than a missed switcher, and this rule is exactly what the markup proves.

The rule, per switcher for language X on a page that declares its own `rel="alternate" hreflang="X"` set: the link's `href` must resolve — the way a static host serves files (`/de/` to its `index.html`, extensionless URLs, the configured `basePath`) — to the very page this page declares as its alternate for X. Language codes are compared without regard to case; the comparison is by resolved page, so `/de/` and `/de/index.html` agree. A finding is reported when the switcher lands on:

- a page of the built site the page does not declare for X,
- this very page (the current page itself),
- a page outside the built site — unless the page's declaration for X names that exact external URL, in which case the site hosts that language elsewhere consistently and passes,
- nothing at all: a page the build does not serve, a non-page `href` such as `mailto:`, or an empty `href`.

Territory, kept clear of the sibling checks so one page problem stays one finding:

- `<link rel="alternate">` elements are never read as switchers: their existence and reciprocity are `i18n.hreflang`'s contract. This check only reads the `<a>` elements people click.
- `x-default` is the fallback marker, not a language: an `<a hreflang="x-default">` is left alone, and a page whose only alternate entry is `x-default` has no alternate set to compare against. What the fallback declares is `i18n.x-default`'s business.
- A page that declares no `rel="alternate" hreflang` set at all is skipped: nothing here can say which page should serve X.
- A page that declares itself as the alternate for its own language may carry a switcher that points at the current page for that language: that is the usual current-language marker, and it passes — a self-pointing switcher is reported only when it does not match its own declaration.

The report points at the `href` attribute of the offending `<a>` itself, so the line and column are exact.

## How to fix

```html
<!-- this page declares its German alternate as /de/about.html -->
<link rel="alternate" hreflang="de" href="/de/about.html">
<!-- before: the German switcher opens the German home page instead -->
<a hreflang="de" href="/de/index.html">Deutsch</a>
<!-- after: it opens the page the declaration names -->
<a hreflang="de" href="/de/about.html">Deutsch</a>
```

When the page declares exactly one alternate for the language, the fix hint carries the exact `href` replacement; when it declares none or several, the hint is manual and names the language and the page the site says should be linked. **Fix it in the source** — the template or i18n plugin that renders the switcher — not only in the built file.
