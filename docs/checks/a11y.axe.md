# a11y.axe

The axe-core rule engine, run in a real browser, reports an accessibility problem in the rendered page.

## Why it matters

Some accessibility rules cannot be decided from parsed HTML alone: computed color contrast and target size depend on browser-computed styles and layout, the DOM that axe sees is the DOM after scripts run, and rules over live shadow DOM need a renderer. When these are wrong, people with low vision, motor disabilities, or screen readers cannot use the page, whatever the markup looks like to a parser.

## What it checks

Runs axe-core (the same rule set Deque Labs ships) over each page rendered in a headless browser, and reports every violation as a finding. Each finding keeps axe's rule ID (`axe <rule-id>: ...`), the CSS selector and an HTML snippet of the offending element, the axe impact mapped to severity (`critical`/`serious` → error, `moderate` → warning, `minor`/undecided → note), and a fix hint with axe's own failure summary.

Two things keep the report from naming one problem twice or drifting into noise:

- Rules the static checks already report (image alt, button and link names, aria attributes, heading order, `<html lang>`, and so on) are disabled here, so a problem has one finding under its source-level check.
- Only rules axe decides are reported; `incomplete` results are not failures.

This check needs a browser and is opt-in: it runs only under `--rendered` (see [ADR 0005](../adr/0005-headless-browser.md)). Pages load from `file://` URLs, the axe script comes from this package's own dependencies, and requests to remote `http(s)` resources are aborted, so a rendered run stays offline. There is no broken fixture for it in the fixture gate for the same reason.

## How to fix

Fix the page's source, not the built file. The finding's fix hint carries axe's failure summary, which names the concrete failure. Two common cases:

```html
<!-- before: text with 2.8:1 contrast on white -->
<p style="color: #b3b3b3">Please review before Friday.</p>
<!-- after: 7:1 on white -->
<p style="color: #595959">Please review before Friday.</p>
```

```css
/* before: a 32×24 px control that fails target size */
.icon-button { width: 24px; height: 24px; }
/* after: meets the 24×24 CSS px minimum in WCAG 2.5.8 */
.icon-button { width: 32px; height: 32px; }
```

For everything else, each axe rule ID has a "Fix any of the following" page at `https://deque.com/axe/axe-core/4.10/documentation/` and in axe's own docs; the rule ID is in the finding message.
