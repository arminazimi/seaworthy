# a11y.autocomplete

An `autocomplete` attribute on a form field is not a valid autofill value.

## Why it matters

The `autocomplete` attribute tells browsers, password managers, and assistive technology what a field is for, so they can fill it in and so users with cognitive or motor disabilities do not have to type their name, email, or address again and again. A misspelled or invented value (`autocomplete="firstname"`) is ignored, and the field loses all of that help. This is also a requirement: WCAG 1.3.5 asks that the purpose of fields collecting personal data can be determined.

## What it checks

The `autocomplete` value on every `<input>` that takes text-like data (not `hidden`, `checkbox`, `radio`, `file`, or button types), `<select>`, and `<textarea>`. A value is valid when it is `on`, `off`, or follows the HTML autofill grammar, in this order:

1. an optional `section-` name, such as `section-billing`
2. an optional `shipping` or `billing`
3. an optional `home`, `work`, `mobile`, `fax`, or `pager`, only before `tel`, `tel-*`, `email`, or `impp`
4. one field name from the HTML autofill list, such as `name`, `given-name`, `email`, `tel`, `street-address`, `postal-code`, `cc-number`, `one-time-code`, or `bday`
5. an optional `webauthn`

`on` and `off` cannot be combined with other tokens. Tokens are not case sensitive. A missing `autocomplete` is not reported, because browsers guess from the field name; this check finds values that are present but wrong.

## How to fix

```html
<!-- before -->
<input name="first" autocomplete="firstname">
<input name="zip" autocomplete="work postal-code">

<!-- after -->
<input name="first" autocomplete="given-name">
<input name="zip" autocomplete="postal-code">
```

The report gives an exact edit when one token is a close misspelling of a field name (`given-nme` to `given-name`). Otherwise it points at the token that is wrong; for a one-time code from an SMS or email, use `one-time-code`.

## Options
