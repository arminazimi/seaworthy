# a11y.tabindex

An element has a `tabindex` greater than 0, so keyboard focus visits it out of reading order.

## Why it matters

Keyboard and screen reader users move through a page with Tab. Any positive `tabindex` jumps that element to the front of the queue, before everything else on the page, so focus leaps around in an order that does not match what people see. The order also breaks every time the page changes.

## What it checks

Any element whose `tabindex` is a whole number greater than 0 (including a written `+2`). `tabindex="0"` (focusable in its natural place) and `tabindex="-1"` (focusable only from script) are fine. Values that are not numbers are ignored here.

## How to fix

```html
<!-- before -->
<button tabindex="3">Save</button>
<!-- after: buttons are focusable already -->
<button>Save</button>

<!-- a custom control that must be focusable -->
<div role="button" tabindex="0">Save</div>
```

The report gives an exact edit that sets `tabindex="0"`. If the element is focusable on its own (links, buttons, form fields), removing `tabindex` is even better. To change the order, move the element in the HTML.

## Options

None.

## Standards

- [WCAG 2.4.3 Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)
