# a11y.table-headers

A data table has no header cells, or a `headers` attribute points at an id that is not on a cell of the same table.

## Why it matters

Screen reader users read a table cell by cell. Header cells (`<th>`) are how they learn what each value means: "Price, 12.50" instead of just "12.50". A table built only from `<td>` cells has no such labels, so the numbers are heard with no context. The `headers` attribute links a cell to specific headers in complex tables; if the ids it lists do not exist, the link is silently dropped.

## What it checks

- **No header cells** (error): a `<table>` with at least 2 rows and 2 columns and no `<th>` cell. Tables with `role="presentation"` or `role="none"` are layout tables by the author's own word, and tables hidden with `hidden` or `aria-hidden="true"` are skipped. One row or one column is not treated as a data table. A nested table is judged on its own cells.
- **headers points nowhere** (error): a cell whose `headers` lists an id that is not the id of a cell in the same table.

## How to fix

```html
<!-- before -->
<table>
  <tr><td>Plan</td><td>Price</td></tr>
  <tr><td>Basic</td><td>$5</td></tr>
</table>

<!-- after -->
<table>
  <tr><th scope="col">Plan</th><th scope="col">Price</th></tr>
  <tr><th scope="row">Basic</th><td>$5</td></tr>
</table>
```

Use `scope="col"` for headers across the top and `scope="row"` for headers down the side. For tables with merged cells, give each header an `id` and list the ids in each data cell's `headers`. If the table is only used to lay out a page, replace it with CSS or add `role="presentation"`. There is no automatic edit, because the report cannot know which cells are headers.
