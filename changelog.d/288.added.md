Two issue forms for the findings people cannot self-serve: **False positive** collects the check ID, the version or commit, how the run happened, the `--format json` report for the page, a minimal reproduction, the `seaworthy.config.json` or its absence, the framework and host behind the built output, and the outcome the reporter expects; **Missing check** collects the failure mode in one sentence, a real site or fixture where it shows, which input deciding it would need (`html`, `files`, `browser`, or the opt-in `network`), and the closest existing check, so triage has the reproduction and the `needs` call up front (#288).
