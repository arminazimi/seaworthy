`layout.horizontal-overflow` reports pages that scroll sideways on a phone. The rendered check (opt-in under `--rendered`, needs a browser) loads each page at the phone viewport (375 CSS px) and reports an `error` when the document is wider than the screen — naming the pan distance and the widest element past the edge — and when sideways overflow is clipped away with `overflow-x: hidden` instead of panned, because hiding the scroll hides the problem, not the page. A wide table or code block that scrolls inside its own viewport-fitting region is allowed, the way WCAG 1.4.10 allows it. The reflow measurement at 320 CSS px stays with `layout.reflow`; no axe-core rule decides sideways document scroll, so `a11y.axe` keeps its silence on this one. Pages load from `file://` and remote requests are aborted; the check skips with a hint when the machine has no browser. (#345)
