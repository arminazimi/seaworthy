`spec/source-map/v0.md` freezes a new versioned contract: a single optional `source-map.json` a theme or generator may publish at a built site's root that names, for a built file and — where the generator can say so — for a section (`anchor`), which repository source file and line produced it, so an agent given a finding on a generated page can open the author's source instead of editing built output. It is deliberately the coarse, markup-level companion to Source Map v3, not a rival: file- and section-level provenance in readable JSON, where v3 stays the right tool for token-level JavaScript and CSS. A `spec` version field stamps it like the report and history records; readers must ignore unknown members, treat every mapping as advisory, and **refuse** any source path that is absolute or escapes the repository root — path traversal is the one thing the format is built to get wrong-proof. No consumer ships: Seaworthy neither reads nor writes this file today, and mapping findings back through it is the separate task `int.source-map`. (#381)
