The composite Action writes a job summary to `$GITHUB_STEP_SUMMARY`: the counts the report contract already carries (pages, findings, per severity) plus the notes it carries (suppressed, baselined, stale baseline entries, readability score), the top findings worst first — severity, then check ID, then file, line and column — up to ten of them with the remainder as a count, the checks that crashed, and the badge state with the README snippet. A new `summary` input turns it off (`on` by default), and a summary that cannot be rendered or written costs the run nothing: the verdict stays the CLI's exit code. Several sites append one labelled section each to the same file. (#260)
