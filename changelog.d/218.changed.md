The engine now runs static built-in checks in parallel: for a site of 2,000 pages or more, the checks that need only the built graph are dispatched to a pool of up to four worker threads (Node's built-in `node:worker_threads`, no new dependency), each working over its own deterministic rebuild of the shared site graph, while rendered, network, and caller-supplied checks keep running on the main thread. The report is unchanged — findings, skipped checks, and errors are assembled at each check's own position, so the JSON is byte-for-byte identical to a sequential run; `SEAWORTHY_WORKERS=1` forces the sequential path. `tools/bench-large.mjs` regenerates a deterministic 10,000-page site from a fixed seed (never committed, offline, writes to a temp folder) and measures both modes against each other, failing if the two reports differ.
