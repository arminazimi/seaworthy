Every check's docs page is now an MCP resource: `resources/list` serves one `seaworthy://checks/<check-id>/docs` entry for each check the server knows, and `resources/read` returns that check's contract page from `docs/checks/` verbatim — the whole why, what it checks, how to fix, and standards page, not only the excerpt `explain_finding` quotes. The list is built from verify's own check metadata, so no id is invented and no other file is addressable: an unknown check id answers with an invalid-params error that points at `list_checks`, and a page a published install does not ship answers with that check's own docs URL. Reads no site and no network, and adds no tool, so `tools/list` is unchanged. (#253)
