Added the benchmark runner: `npm run bench:run` (`tools/bench-run.mjs`) executes the task suite from #101 instead of only validating it. For every task in `planning/bench/tasks.json` it builds that task's workspace in its own temp directory (`task.start` copied to `site/`, every seed beside it), runs each criterion through the real built CLI as an argv array with no shell, applies the task's scripted reference edit — the fix step stays the runner's own, since Seaworthy reports and suggests and never rewrites a site — and re-runs the criteria, so the verdict is still the documented exit code alone (0/1/2/4). It scores every task and prints a summary line, `--json` emits the same report deterministically (fixed key order, workspace-relative locations, no timestamps and no temp paths) for CI to diff, `--task <id>` scores one task and `--list` shows the plan without running anything; a failing gate also prints the findings still open at its `--fail-on` level with their fix hints, and a `fix --dry-run` preview is recorded per task to show what Seaworthy would suggest. The runner proves its own boundary: it snapshots the workspace before and after every CLI run and marks the task invalid if any file outside the engine's own `.seaworthy/` run record changed. Nothing here touches the task definitions, no network or browser flag reaches the CLI, and the benchmark stays out of `npm run check` — it is a measurement, not a gate. (#102)
