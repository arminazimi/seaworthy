`npm run bench:1000` measures the 1,000-page performance budget: `tools/bench-1000.mjs` generates a deterministic 1,000-page built site (seed 20261102, no network, nothing committed), verifies it with the built CLI as its own process, prints the machine, Node version, page count, findings and the wall time of each run, checks the report JSON is byte-identical across runs, and exits non-zero when the best of three runs is slower than 30 s; `packages/verify/tests/perf-1000.test.ts` freezes what that claim rests on without touching the clock — the generator writes exactly 1,000 pages and the same bytes twice, the report counts one entry per page, and `--timings` emits its stage and check summary. The gate itself stays a standalone command rather than a step of `npm run check`, because a wall-clock assertion inside a suite that runs many processes at once measures the runner, not the engine.
