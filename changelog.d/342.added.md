The MCP server gained the `wait_for_build` tool: it sits on the built site folder with the same recursive `fs.watch` and the same settle window that `--watch` uses, and when a build lands it runs the checks once and returns the same report JSON as `verify_site`, then stops. The wait is bounded by construction — `timeout_ms` defaults to 30000 ms and is capped at 600000 — a cancelled request closes the watcher, and the folder it watches is the one the caller named: never the workspace itself, never a folder above it, not even through a symlink.
