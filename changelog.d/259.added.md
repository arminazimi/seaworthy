The GitHub Action can now pin findings to the lines they belong to: on a pull-request run it echoes inline annotations (`::error`, `::warning`, `::notice`) for the findings whose file and line exist in the checkout and whose file this pull request actually touched, read from `git diff` against the base branch, never from the network and never with a guessed line number. Findings with no line (page-level and `selector`-only ones), files the pull request did not touch, and everything past the 50-annotation budget go to the summary channel instead, each with its reason, so nothing is dropped and no pull request gets 300 warnings. The report's `error`, `warning` and `note` map to the runner's three annotation levels, and workflow-command values are escaped (`%`, `\r`, `\n`, plus `]` and `:` in a `file=` value) so a finding message cannot break out of the command. The new `annotations` input (`auto`, the default, or `off`) turns it down. The exit code stays the CLI's alone: annotations never move the verdict, and `threshold: none` still annotates. (#259)
