`layout.text-clipped` reports text cut off by its own container. Rendered checks only (`--rendered`): for every box whose computed `overflow` is `hidden` or `clip`, the browser's `scrollWidth`/`scrollHeight` against its `clientWidth`/`clientHeight`, and the layout of the box's own text against its padding edge, so a thumbnail that crops a photograph stays silent while a fixed-height card that swallows the third line does not. Each finding names the clipped element by selector and markup, the axis, how many CSS px of text sit outside the box, and the phone, tablet, and desktop widths it was cut at; the page itself is never the clipped element, so a page that scrolls sideways remains `layout.horizontal-overflow`'s finding, and an ellipsis the author asked for with `text-overflow` stays a design choice rather than a defect. Tune the threshold with `checks."layout.text-clipped".options.minPixels`, default 3. (#348)
