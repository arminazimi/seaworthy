Findings can now name the source behind the built file they point at. `seaworthy verify` reads the optional `source-map.json` a theme or generator publishes at the built site's root, per `spec/source-map/v0.md`, and a finding on `docs/guide/index.html` — or on its `#installation` section, when the map carries an `anchor` entry — gains an additive, optional `sourceLocation` with the repository file and line that produced it, so an agent edits the author's source instead of generated output. Where a build publishes no map, or leaves a page out of it, what the generator itself exposes answers the same question: a Markdown source that declares its published path in front matter (`permalink:`) names the page it builds, and its headings name the line an anchor's section starts on (the sources are the ones `--markdown` already points at). Everything about the mapping is advisory, exactly as the contract demands: it changes no finding, no severity, and no exit code, and an absent, unreadable, or stale map — or a `source` or `target` that is absolute, escapes its root, or names a page the build does not serve — is refused entry by entry and degrades to the built-output location, never to a guessed path. A run's fix prompts say `its source is docs/guide.md:10` when they know it, and a site that publishes nothing produces the report bytes it produced before. (#197)
