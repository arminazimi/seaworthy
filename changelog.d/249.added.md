The MCP server gained the `fix_preview` tool: give it a built site folder and it verifies the site and returns every edit the findings' suggested fixes would make as ONE unified diff — the same preview `seaworthy fix --dry-run` prints, produced by verify's own fix planner — and writes nothing, because there is no mode that writes. Findings that cannot become a safe edit (manual fixes, edits that need content only a person can supply, and edits whose anchor no longer matches the built file) come back in `manual` with the reason instead of guessed hunks, so the preview is exactly what the fix path would apply. The result JSON says so itself: `written` is always false and a note tells the caller the diff is a preview to apply with `git apply`. (#249)
