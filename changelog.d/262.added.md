The Seaworthy Action verifies several sites in one repository: the `site` input now takes a list of built folders — one per line or comma — and runs one verify per folder, reporting every site with its own findings count and its own SARIF file (`<name>.<site>.<sarif>` when several sites share the `sarif` input path) so one site's failure never hides another's. The run fails if any site fails: exit 2 when the CLI rejected a site, else 4 when a check crashed, else 1 when any site has findings at the threshold. One site — with or without the `site` input — keeps the previous behaviour byte for byte, the threshold and the `markdown` input stay global, folder names with spaces work, sites outside the workspace are rejected, and no monorepo config format was invented: the workflow already knows its own package folders.
