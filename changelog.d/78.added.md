The MCP server gained the `explain_finding` tool: given a finding from the report JSON of `verify_site`, or just a check id, it returns the fix hint, the URL of the check's contract page, and the before/after example from that page, plus the finding's ready edits and prompt when it carries them. The check metadata comes from verify's published check list and the example from the check's own docs page, so no fix text lives in the MCP package; an unknown check id answers with a clear error, never an invention.
