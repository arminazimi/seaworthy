The MCP tools `verify_site` and `verify_changed` now send standard `notifications/progress` during a run when the caller passes `_meta.progressToken`, the MCP SDK's own per-call opt-in: the run started, how many pages were parsed, that the checks are running, one update per finding the moment its check finishes, and the finish. The engine exposes no per-page event stream or total-work figure, so progress never claims a percentage and sends no `total`; a call without a progress token gets no notifications and the byte-identical report.
