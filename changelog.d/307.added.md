`seaworthy verify --fetch <url>` verifies pages over HTTP: each address you name is fetched once and written into a temporary snapshot that the existing site graph reads, so every folder check works on a deployed page unchanged. It is opt-in, and a run without it makes exactly the bytes it made before. The caps are ADR 0011's - 500 pages, 5 MB per response, 5 redirects and 10 seconds per address, no cookies or credentials, non-HTTP(S) schemes and private address literals refused (a loopback address you typed is always allowed, `--allow-private` covers a site reachable only from here) - and every refusal is named on stderr, never dropped silently. Nothing is discovered from links or sitemaps, robots.txt is not consulted, and the MCP server and the GitHub Action do not expose the flag. (#307)
