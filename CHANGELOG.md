# Changelog

## Unreleased

### Added

- The repository root ships a composite `action.yml`: it builds Seaworthy from source, runs `seaworthy verify` once against the workflow's checkout, writes an optional SARIF 2.1.0 report (pinned `actions/upload-artifact` upload), and exits 1 when findings reach the `threshold` input, with `site`, `threshold`, and `sarif` inputs (#88).
- `seaworthy fix [dir] --dry-run` runs the checks and prints one unified diff of every edit the suggested fixes would apply to the built output, with `a/` and `b/` paths relative to the site folder so `git apply` applies it in one step; no file is ever written or edited, findings that cannot become safe edits are listed on stderr as manual guidance with a reason and the fix hint, and identical edits proposed by two checks are planned once (#336).
- `a11y.axe` runs axe-core in a real headless browser over each page (`--rendered`, opt-in) and reports violations the static checks cannot decide, such as computed color contrast and target size, with axe's rule ID, impact-mapped severity, selector, and HTML snippet; it uses a browser the machine already has (`--browser-path`, `SEAWORTHY_BROWSER`, then an installed Chrome, Chromium, or Edge), loads pages from `file://` URLs, aborts remote requests to stay offline, and reports a missing browser or `playwright-core` as a skipped check, never as a pass (#64).
- `seaworthy verify --format html` writes one self-contained report page: summary counts at the top, findings grouped by file and then check, filters for severity, check, and file, and skipped and crashed checks in their own sections; one file with inline CSS and vanilla JavaScript, no external requests, no timestamps, so the same report is byte-identical every run (#338).
- `quality.page-weight` reports a page that loads more bytes of HTML, CSS, JavaScript, images, or fonts than its budget allows: sizes come from the built output's file system with no browser and no network, the finding names the page, the bucket, the budget, the actual weight, and the exact position the heaviest asset is attributed from, and the check is off until a site sets `checks."quality.page-weight".options.budgets`, so runs are byte-identical with and without it (#331).
- `--format ndjson` writes one JSON finding per line as each check finishes, so an agent can read results live: every line carries exactly the fields of one finding in `--format json`, including its fix prompt, and line order follows check completion, so each line alone is deterministic while the report keeps its sorted order (#266).
- `seaworthy verify --watch` re-verifies whenever the build folder changes and, after the first full report, prints only what changed: one `+` line per new and one `-` line per fixed finding under a counting headline. Bursts of writes are debounced into one re-run, a re-run never enters while one is in flight, and Ctrl-C closes the watcher. No new flag combination changes how a run without `--watch` behaves (#337).
- The exit code is now decided from every finding the engine reported, capped or not: `summary.bySeverity` stays uncapped, so a run with `--max-findings` no longer exits 0 when the findings it cut included a failing severity (#217).
- `--max-findings <n>` (default 1000) and a per-check `maxFindings` config key keep a broken site from producing a giant report: the report keeps the first n findings in report order, counts the rest as `summary.findingsOmitted`, and is byte-identical when nothing is cut (#217).
- Every `verify` run records a deterministic JSON summary — timestamp, site root and page count, finding counts by severity and by check, and a hash of the run's settings — in `.seaworthy/history`, keeping the most recent 30 runs and pruning the oldest, so runs can be diffed and trends read. Opt out with `"history": false` in the config or `--no-history` for one run; the report and machine-readable output are byte-identical either way (#339).
- `seaworthy verify --format prompt` exports all findings as one copy-pasteable prompt an agent can work through in order: findings grouped by file (fewest findings first, so quick wins land early; one group per file), each file a heading with compact fix-first lines and exact locations, ending with the instruction to rebuild and re-run verify (#341).

- The status badge is a pure function of the verify report: `badgeForReport` (in `packages/action/src/badge-svg.ts`, exposed by the new `seaworthy-badge` CLI in `@seaworthy/action`) reads a report's `summary.bySeverity` counts and crashed-check `errors` and emits a deterministic, byte-identical SVG — teal `passing`, amber `warnings`, red `errors` under the same scheme as the default `--fail-on error` gate — plus the README snippet it is shown with. Served by GitHub from a file a CI workflow commits; no hosted service (docs/badge.md) (#90).
- The status badge is a pure function of the verify report: `badgeForReport` (in `tools/brand/badge.mjs`, exposed by the new `seaworthy-badge` CLI in `@seaworthy/action`) reads a report's `summary.bySeverity` counts and crashed-check `errors` and emits a deterministic, byte-identical SVG — teal `passing`, amber `warnings`, red `errors` under the same scheme as the default `--fail-on error` gate — plus the README snippet it is shown with. Served by GitHub from a file a CI workflow commits; no hosted service (docs/badge.md) (#90).
- `seaworthy verify --format llm` prints a compact report sized for an agent's context window: one line per finding, grouped by file, with the fix first, then the check ID, severity, location, and a short evidence line; plain text, no color, byte-identical everywhere (#263).
- `i18n.hreflang` reports `rel="alternate" hreflang=...` entries that point at a page the built site does not serve, or whose target page declares no hreflang alternate for the declaring page's language back to it; language values match without regard to case, `x-default` entries are out of scope (the `i18n.x-default` follow-up handles them), and external hreflang URLs are skipped, never fetched (#368).
- Every output format now carries ready-to-paste fix prompts: one per finding and one for the whole report, generated from each finding's data alone (check ID, location, fix hint) so they are identical, deterministic, and free of private run state everywhere (#264).
- `quality.empty-pages` reports pages whose built HTML has no main text — an empty `<main>`, or no text outside the navigation, header, and footer — so an agent that reads it gets only the site frame (#329).
- `html.nesting` reports content models the parser accepts but browsers mishandle: interactive elements inside interactive ones, block elements inside `<p>`, and nested `<a>` or `<button>`, each at the inner element's exact location with a fix hint (#244).
- `hosting.headers` and `hosting.redirects` validate the `_headers` and `_redirects` files of Netlify and Cloudflare Pages: malformed lines, splats and placeholders the hosts cannot match, paths and destinations the built site does not serve, dead duplicate rules, and redirects that answer their own address (#325).
- `npm run check:startup` gates `seaworthy --version` at the 150 ms startup budget from ADR 0004: one warm-up, five timed runs judged on the best run, with settle-delayed retry passes (up to 15 runs) so a loaded CI runner does not flakily fail (#299).
- `html.inline-handlers` reports inline event handlers (`onclick` and every other `on*` attribute) and `javascript:` URLs in navigation and form attributes, which a strict Content Security Policy (`script-src` without `"unsafe-inline"`) blocks (#247).
- `seaworthy diff before.json after.json` compares two report files and prints one JSON object with the counts and finding lists for what is new, fixed, and unchanged (#335).
- `seaworthy config check` validates a config with the same rules `verify` applies, without running any checks, and exits 0 or 2 (#293).
- The CLI colors human output when the stream is an interactive terminal: severity tokens in the pretty report, the `seaworthy:` summary lines, and crash notices get color, `NO_COLOR` turns it off everywhere, and JSON, markdown, SARIF, and report files are never colored (#291).
- `a11y.iframe-title` reports iframes with missing or blank titles, with source locations and a manual fix hint (#232).
- `html.obsolete` reports obsolete elements and presentational attributes (`<center>`, `<font>`, `<marquee>`, `align`, `bgcolor`, and similar) with exact source locations and CSS fix hints (#245).
- `seaworthy verify --timings` prints time per stage and per check to stderr. The report is unchanged, so default output stays deterministic (#216).
- `html.charset` reports pages with no character encoding declaration, or one declared after the first 1,024 bytes, with the exact location and a fix hint (#243).
- `social.twitter-card` reports pages without a usable Twitter card type, and cards that have no image and no Open Graph fallback (#61).
- `social.image-size` reports social preview images below the platform minimum dimensions or over the 5 MB limit, reading only images inside the built site (#61).
- `html.meta-refresh` reports `<meta http-equiv="refresh">` with a delay greater than 0 seconds, which moves people before they can read (WCAG 2.2.1) (#246).
- `html.redirect-chain` follows meta-refresh redirects page by page and reports chains of redirect pages (a warning at the chain's start, naming the final destination) and loops that never land on content (an error) (#333).
- `meta.canonical-target` reports pages whose canonical link resolves, the way a static host serves it (including `basePath`), to no page in the built site (#334).
- `meta.canonical-cycle` reports pages whose canonical links point at each other in a circle of two or more, so no page in the circle has a canonical URL (#334).
- `meta.duplicate-description` groups pages whose `<meta name="description">` is the same text into one finding that names the description and every page carrying it (#328).
- `html.doctype` reports pages with no doctype, or a non-standard one that puts the browser in quirks mode (#242).
- `html.parse-errors` reports the HTML parser's own errors (stray end tags, bad nesting, duplicate attributes) at exact positions (#241).
- `quality.orphans` reports pages that no other page links to (#326).
- `meta.duplicate-titles` groups pages that share the same `<title>` into one finding (#327).
- `quality.not-found-page` reports a missing 404 page, or one that is empty or only redirects (#330).

### Fixed

- Only an immediate redirect (`content="0; url=..."`), or a refresh with a destination whose page has no readable text, now counts as a redirect stub, so content checks such as `meta.title` run on pages whose delayed `<meta http-equiv="refresh">` still shows content (#421).
