## Goal
Report pages that use characters outside every `unicode-range` of the `@font-face` rules their font stack names.

## Files

**Create**
- `packages/verify/src/checks/i18n-unicode-range.ts`
- `packages/verify/tests/i18n-unicode-range.test.ts`
- `docs/checks/i18n.unicode-range.md`
- `fixtures/broken/i18n-unicode-range/`

Touch no other file. If one must change, stop and say why in the issue.

## Steps
1. Export a `Check` with ID `i18n.unicode-range` from `packages/verify/src/checks/i18n-unicode-range.ts`; the build discovers it, so edit no registry.
2. Uses the CSS model; list the first missing characters.
3. Fix hint: add the range or a font that covers it.
4. Scope: only pages and elements that `foundation.rtl-scope` marks as right-to-left, unless the rule says otherwise.
5. Fixture `fixtures/broken/i18n-unicode-range/` with `site/`, `expected.json` (exact findings with line and column), and `fixture.json` limited to this check.
6. Docs page `docs/checks/i18n.unicode-range.md` with Why it matters, What it checks, and How to fix (before and after, in Persian or Arabic where it applies).

## Done when
- [ ] The check reports every case in its broken fixture with exact locations, and nothing on any clean fixture (including `fixtures/clean/rtl-*`).
- [ ] Every finding has a fix hint; where a safe edit exists, the finding carries it as an `Edit`.
- [ ] The docs page exists and `npm test` finds it.
- [ ] `npm run check` passes.
