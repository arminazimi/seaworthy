## Goal
Report Latin-script sentences of 6 or more words on pages whose language is right-to-left (and the reverse), outside code, quotes, and elements with their own `lang`.

## Files

**Create**
- `packages/verify/src/checks/i18n-untranslated-text.ts`
- `packages/verify/tests/i18n-untranslated-text.test.ts`
- `docs/checks/i18n.untranslated-text.md`
- `fixtures/broken/i18n-untranslated-text/`

Touch no other file. If one must change, stop and say why in the issue.

## Steps
1. Export a `Check` with ID `i18n.untranslated-text` from `packages/verify/src/checks/i18n-untranslated-text.ts`; the build discovers it, so edit no registry.
2. Brand names and single terms are fine.
3. Fix hint: translate the text, or mark it with `lang` if it is intentional.
4. Scope: only pages and elements that `foundation.rtl-scope` marks as right-to-left, unless the rule says otherwise.
5. Fixture `fixtures/broken/i18n-untranslated-text/` with `site/`, `expected.json` (exact findings with line and column), and `fixture.json` limited to this check.
6. Docs page `docs/checks/i18n.untranslated-text.md` with Why it matters, What it checks, and How to fix (before and after, in Persian or Arabic where it applies).

## Done when
- [ ] The check reports every case in its broken fixture with exact locations, and nothing on any clean fixture (including `fixtures/clean/rtl-*`).
- [ ] Every finding has a fix hint; where a safe edit exists, the finding carries it as an `Edit`.
- [ ] The docs page exists and `npm test` finds it.
- [ ] `npm run check` passes.
