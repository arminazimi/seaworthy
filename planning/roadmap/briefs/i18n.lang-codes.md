## Goal
Report `lang` and `hreflang` values that are not valid BCP 47 or use legacy codes (`iw`, `ji`, `in`, `per`, `fa_IR` with an underscore).

## Files

**Create**
- `packages/verify/src/checks/i18n-lang-codes.ts`
- `packages/verify/tests/i18n-lang-codes.test.ts`
- `docs/checks/i18n.lang-codes.md`
- `fixtures/broken/i18n-lang-codes/`

Touch no other file. If one must change, stop and say why in the issue.

## Steps
1. Export a `Check` with ID `i18n.lang-codes` from `packages/verify/src/checks/i18n-lang-codes.ts`; the build discovers it, so edit no registry.
2. Fix hint: use the modern code (`he`, `yi`, `id`, `fa`, `fa-IR`).
3. Scope: only pages and elements that `foundation.rtl-scope` marks as right-to-left, unless the rule says otherwise.
4. Fixture `fixtures/broken/i18n-lang-codes/` with `site/`, `expected.json` (exact findings with line and column), and `fixture.json` limited to this check.
5. Docs page `docs/checks/i18n.lang-codes.md` with Why it matters, What it checks, and How to fix (before and after, in Persian or Arabic where it applies).

## Done when
- [ ] The check reports every case in its broken fixture with exact locations, and nothing on any clean fixture (including `fixtures/clean/rtl-*`).
- [ ] Every finding has a fix hint; where a safe edit exists, the finding carries it as an `Edit`.
- [ ] The docs page exists and `npm test` finds it.
- [ ] `npm run check` passes.
