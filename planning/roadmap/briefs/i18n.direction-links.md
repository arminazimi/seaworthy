## Goal
Report links in a language switcher whose text is in an RTL language but has no `lang` and `dir`, so it is read and shown wrong on LTR pages.

## Files

**Create**
- `packages/verify/src/checks/i18n-direction-links.ts`
- `packages/verify/tests/i18n-direction-links.test.ts`
- `docs/checks/i18n.direction-links.md`
- `fixtures/broken/i18n-direction-links/`

Touch no other file. If one must change, stop and say why in the issue.

## Steps
1. Export a `Check` with ID `i18n.direction-links` from `packages/verify/src/checks/i18n-direction-links.ts`; the build discovers it, so edit no registry.
2. Reuse the switcher detection from `i18n.switcher`.
3. Fix hint: add `lang` and `dir` to each language name.
4. Scope: only pages and elements that `foundation.rtl-scope` marks as right-to-left, unless the rule says otherwise.
5. Fixture `fixtures/broken/i18n-direction-links/` with `site/`, `expected.json` (exact findings with line and column), and `fixture.json` limited to this check.
6. Docs page `docs/checks/i18n.direction-links.md` with Why it matters, What it checks, and How to fix (before and after, in Persian or Arabic where it applies).

## Done when
- [ ] The check reports every case in its broken fixture with exact locations, and nothing on any clean fixture (including `fixtures/clean/rtl-*`).
- [ ] Every finding has a fix hint; where a safe edit exists, the finding carries it as an `Edit`.
- [ ] The docs page exists and `npm test` finds it.
- [ ] `npm run check` passes.
